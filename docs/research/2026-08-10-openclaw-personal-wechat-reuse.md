# Reusing OpenClaw's “personal WeChat channel” in Pi or another application

**Researched:** 2026-08-10  
**Scope:** Current official repositories, source code, package metadata, official docs/issues, and release/tag history. “Verified” means the cited primary source states or implements it; “Inference” is explicitly labeled.

## Executive conclusion

**Yes—if “OpenClaw personal WeChat” means the current Tencent ClawBot/iLink channel.** Two Pi extensions already implement that transport: [`pi-wechat`](https://pi.dev/packages/pi-wechat?page=42) and [`@wechatbot/pi-agent`](https://github.com/corespeed-io/wechatbot/tree/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent). The latter is built on a reusable, OpenClaw-independent SDK, [`@wechatbot/wechatbot`](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/README.EN.MD), whose repository explicitly says it was inspired by Tencent’s `openclaw-weixin` and also supplies Python, Go, and Rust implementations. A second general bridge, [`weixin-agent-sdk`](https://github.com/wong2/weixin-agent-sdk), explicitly says it was modified from `@tencent-weixin/openclaw-weixin` and exposes a small arbitrary-`Agent` interface plus ACP adapters.

**The official Tencent package itself is not a drop-in general SDK.** Its manifest requires OpenClaw, its entrypoint registers an OpenClaw channel, and ten production TypeScript files import OpenClaw plugin-SDK surfaces; however, its HTTP protocol, wire types, QR login, media crypto, and polling layers are visibly modular and MIT-licensed, so extraction or reimplementation is practical ([manifest](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/package.json), [entrypoint](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/index.ts), [protocol implementation](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/api/api.ts), [MIT license](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/LICENSE)).

**If the phrase instead means `freestylefly/openclaw-wechat`, whose title literally says it connects OpenClaw to a personal WeChat account, the answer is different.** That project uses a paid/private proxy API plus an inbound public webhook rather than Tencent’s ClawBot/iLink bot channel; no Pi adapter for that exact proxy endpoint appeared in the checked public-code search, and its open client can be extracted only if the private API remains available ([README](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/README.md), [proxy client](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/src/proxy-client.ts), [GitHub code search](https://github.com/search?q=%22%2Fv1%2FiPadLogin%22+%22pi-package%22&type=code)). It carries materially higher account, trust, webhook, and reproducibility risk than the Tencent route.

## 1. What “OpenClaw personal WeChat channel” refers to

### Canonical current meaning: Tencent Weixin ClawBot/iLink

OpenClaw’s current official WeChat documentation defines **WeChat** as an external plugin maintained by the Tencent Weixin team: npm package `@tencent-weixin/openclaw-weixin`, plugin/channel id `openclaw-weixin`, with `weixin` and `wechat` aliases ([OpenClaw WeChat docs](https://docs.openclaw.ai/channels/wechat)). The plugin lives in Tencent’s separate [`Tencent/openclaw-weixin`](https://github.com/Tencent/openclaw-weixin) repository rather than OpenClaw core, and Tencent’s source calls the backing endpoints at `https://ilinkai.weixin.qq.com` and the media CDN at `https://novac2c.cdn.weixin.qq.com/c2c` ([account constants](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/auth/accounts.ts)).

Despite the colloquial word “personal,” this is **not personal-account impersonation**. A Tencent repository collaborator states that QR authorization attaches a separate ClawBot to the user’s WeChat, that messages flow through that bot, and that sending as the user’s own account to the user’s friends is not supported or planned ([issue #52 maintainer response](https://github.com/Tencent/openclaw-weixin/issues/52#issuecomment-4407647606)). The plugin metadata declares direct chats only, while OpenClaw’s docs say media is supported and group chats are not advertised ([channel capability source](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/channel.ts), [OpenClaw WeChat docs](https://docs.openclaw.ai/channels/wechat)).

## 2. Tencent plugin architecture and protocol

### End-to-end flow — verified

1. OpenClaw loads the external package manifest, invokes its entrypoint, and the entrypoint registers `weixinPlugin` through `api.registerChannel(...)` ([entrypoint](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/index.ts), [OpenClaw architecture summary](https://docs.openclaw.ai/channels/wechat)).
2. `openclaw channels login --channel openclaw-weixin` starts QR login; confirmation returns a bearer bot token, bot/account identifiers, and potentially a server-selected base URL, which the plugin stores under the OpenClaw state directory ([README login flow](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md), [QR implementation](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/auth/login-qr.ts), [account storage](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/auth/accounts.ts)).
3. For each configured account, a monitor repeatedly calls `getupdates`, persists the returned `get_updates_buf` cursor, normalizes each message, and dispatches it through OpenClaw’s channel runtime; it retries failures, backs off after three consecutive failures, and treats error `-14` as a stale token requiring a pause/recovery path ([monitor loop](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/monitor/monitor.ts)).
4. Replies call `sendmessage` and must return the inbound conversation’s `context_token`; `getconfig` supplies a typing ticket and `sendtyping` toggles the typing indicator ([official protocol README](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md), [send implementation](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/messaging/send.ts)).
5. Images, voice, files, and video use WeChat CDN references; upload calls `getuploadurl`, encrypts media with AES-128-ECB, uploads ciphertext, and sends the returned encrypted reference ([official protocol README](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md), [CDN crypto](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/cdn/aes-ecb.ts)).

The wire transport is HTTP/JSON rather than WebSocket: authenticated POSTs use `AuthorizationType: ilink_bot_token`, `Authorization: Bearer <token>`, and a random base64 `X-WECHAT-UIN`; the major methods are `getupdates`, `sendmessage`, `getuploadurl`, `getconfig`, and `sendtyping` ([official protocol README](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md), [HTTP implementation](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/api/api.ts)). Tencent’s public developer documentation separately documents QR acquisition/status returning `bot_token`, `ilink_bot_id`, `ilink_user_id`, and `baseurl`, corroborating that this is a bot-channel credential flow ([Weixin developer docs](https://developers.weixin.qq.com/doc/aispeech/knowledge/openapi/Clawbotrelated.html)).

### Dependencies and host coupling — verified

The current package is version 2.4.6, requires Node.js 22+, directly depends only on `qrcode-terminal` and `zod`, and declares OpenClaw `>=2026.5.12` as a peer and minimum host ([package manifest](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/package.json), [npm package](https://www.npmjs.com/package/@tencent-weixin/openclaw-weixin)). The README’s older compatibility table still says early 2.x supports `>=2026.3.22`, while the manifest and changelog record the later minimum-host bump; the manifest is the current enforceable metadata ([README](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md), [changelog](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/CHANGELOG.md)).

The separation boundary is real but incomplete: protocol/types/CDN/storage/auth/monitor/channel are separate modules, yet the channel, monitor, message processor, account store, pairing, hooks, logger, and configuration paths import OpenClaw plugin SDK modules ([source tree](https://github.com/Tencent/openclaw-weixin/tree/cef0bfc390393f716903e16d50408118047f87e0/src), [channel imports](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/channel.ts), [message processor imports](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/messaging/process-message.ts)). Even the low-level HTTP module reaches into the account configuration and OpenClaw-oriented logger, so deep-importing it is not a clean public-library boundary ([HTTP module imports](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/api/api.ts)).

**Inference:** The clean extraction seam is below `process-message.ts`: keep/reimplement QR auth, API/types, cursor/context-token storage, message parsing, and CDN code; replace `monitor -> processOneMessage -> OpenClaw channelRuntime` with an application callback, and replace outbound OpenClaw dispatch/hooks with the application’s response handler. This inference follows the monitor’s explicit pipeline and the generic SDKs that independently implement exactly that seam ([monitor](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/monitor/monitor.ts), [`@wechatbot/wechatbot` architecture](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/docs/architecture.md)).

### Focused follow-up: group-chat support

**Conclusion: current ClawBot/iLink should be treated as direct-chat-only.** QR authorization does not provide a documented or supported way to invite the resulting ClawBot into an existing personal WeChat group, and there is no verified current group-event/reply path in Tencent’s plugin, `pi-wechat`, or CoreSpeed’s SDK/Pi bridge. The optional `group_id` in two low-level wire interfaces is a schema clue, not evidence that the hosted service currently delivers group chats.

- **(a) Official advertised capability:** OpenClaw’s official channel page says direct chats and media are supported while groups are not advertised; Tencent’s plugin metadata declares only `chatTypes: ["direct"]`, its outbound mode is `direct`, and its normalizer always emits `ChatType: "direct"` ([OpenClaw docs](https://docs.openclaw.ai/channels/wechat), [Tencent capability metadata](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/channel.ts#L179-L193), [Tencent inbound normalization](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/messaging/inbound.ts#L220-L239)). It also passes `isGroup: false` through authorization and routes the peer as `direct`, so the implementation is not merely under-advertising a working group path ([message processing](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/messaging/process-message.ts#L172-L198), [direct routing](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/messaging/process-message.ts#L216-L228)).
- **(b) Wire fields that could be mistaken for support:** Tencent’s `WeixinMessage` type contains `from_user_id`, `to_user_id`, `session_id`, and optional `group_id`; CoreSpeed mirrors those fields ([Tencent wire type](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/api/types.ts#L179-L195), [CoreSpeed wire type](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/src/protocol/types.ts#L129-L143)). However, Tencent’s published protocol table omits `group_id`, and neither `MessageItem` schema exposes a structured mention list, mentioned-user IDs, group-member nickname, or equivalent metadata ([Tencent protocol table](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md#L275-L288), [message item and envelope types](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/api/types.ts#L160-L195)). Thus the raw shape could theoretically carry a group ID plus one sender ID, but current primary sources do not establish that the server populates those fields for group events or represents `@mention` semantically.
- **(c) Experimentally reported behavior:** a CoreSpeed issue reporter said messages from another account and from groups did not arrive, including after setting both DM and group policy to `open`; this is a single user report, not a controlled Tencent test or maintainer confirmation ([CoreSpeed issue #74](https://github.com/corespeed-io/wechatbot/issues/74), [policy/result comment](https://github.com/corespeed-io/wechatbot/issues/74#issuecomment-4325168192)). More authoritatively for current SDK expectations, a CoreSpeed collaborator answered two “invite the bot to a group” questions with “WeChat currently does not support this,” adding that the SDK would follow if WeChat later enables it ([issue #50 maintainer answer](https://github.com/corespeed-io/wechatbot/issues/50#issuecomment-4259092950), [issue #53 maintainer answer](https://github.com/corespeed-io/wechatbot/issues/53#issuecomment-4258869385)).
- **(d) Future or unsupported possibilities:** Tencent has open, unimplemented requests for exactly the missing flows—invite ClawBot to a WeChat group, receive messages when it is `@`-mentioned, and reply there—but no Tencent maintainer has confirmed availability or a roadmap in those threads ([Tencent issue #42](https://github.com/Tencent/openclaw-weixin/issues/42), [issue #152](https://github.com/Tencent/openclaw-weixin/issues/152), [issue #236](https://github.com/Tencent/openclaw-weixin/issues/236)). The wire `group_id` may therefore be reusable if the service changes, but it should not be presented as latent, testable support today.

**Operational details:** replies require the inbound conversation’s `context_token`: Tencent’s protocol says it “must be passed back when replying,” CoreSpeed’s `reply()` passes the token from the inbound object and `send()` refuses when no prior token exists, and `pi-wechat` likewise caches by sender and throws without one ([Tencent protocol](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md#L275-L288), [CoreSpeed reply/send](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/src/core/client.ts#L270-L298), [`pi-wechat` context cache](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/client.ts#L66-L98)). An open contributor PR reports that missing or stale tokens are silently dropped by iLink despite HTTP 200, but that report remains unmerged and unconfirmed by a Tencent maintainer ([Tencent PR #247](https://github.com/Tencent/openclaw-weixin/pull/247)). There is consequently no verified group-specific token scope to document. CoreSpeed preserves `group_id` only in `raw` while its public parser exposes the sender as `userId`; `pi-wechat` omits `group_id` from its wire type entirely, and neither bridge implements mention gating or group/member routing ([CoreSpeed parser](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/src/message/parser.ts#L78-L90), [`pi-wechat` types](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/types.ts#L61-L70)).

## 3. Existing Pi extensions

### A. `pi-wechat` — simplest direct Pi implementation

`pi-wechat` is listed in Pi’s package directory as an MIT-licensed extension installable with `pi install npm:pi-wechat`; its manifest points Pi at `./index.ts` ([Pi package page](https://pi.dev/packages/pi-wechat?page=42), [source manifest](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/package.json)). It independently implements QR login, the iLink HTTP calls, cursor polling, context-token caching, typing state, and text sending, then injects inbound text with `pi.sendUserMessage()` and returns the final assistant text on `agent_end` ([API client](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/api.ts), [Weixin client](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/client.ts), [Pi bridge](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/index.ts)).

Its strengths are small size, an explicit queue that serializes inbound prompts, credentials written with mode `0600`, and no OpenClaw runtime dependency ([queue/bridge source](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/index.ts), [credential storage](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/auth.ts)). Its documented limits are text-first operation, media represented as placeholder text, one shared Pi session rather than per-user routing, and no multi-user routing server ([README](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/README.md)).

Maintenance is weak: the repository has only two commits, both on 2026-03-23, and npm remains at 0.1.0 ([latest commit](https://github.com/yangyang0507/pi-wechat/commit/8f351ce82ac6a15c09581e6f9c8c7678e44f055f), [npm package](https://www.npmjs.com/package/pi-wechat)). Its peer dependency still names the former `@mariozechner/pi-coding-agent` package rather than the current `@earendil-works` package ([manifest](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/package.json)).

### B. `@wechatbot/pi-agent` — richer Pi bridge over a reusable SDK

`@wechatbot/pi-agent` is an MIT-licensed Pi package whose manifest loads `src/index.ts` and depends on `@wechatbot/wechatbot` plus `qrcode-terminal` ([Pi package manifest](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/package.json), [npm package](https://www.npmjs.com/package/@wechatbot/pi-agent)). Its source uses `WeChatBot` for QR login, polling, typing, context-token-aware replies, media upload/download, and credential persistence; it sends text/images to Pi, reads text files, saves video to a temporary path, uses voice transcription when present, and sends generated media back ([extension source](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/src/index.ts), [extension README](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/README.md)).

The published Pi extension is 0.1.3 from 2026-04-07, while its underlying Node SDK is 2.2.0 from 2026-07-01 and the repository’s latest commit is 2026-07-02 ([Pi npm package](https://www.npmjs.com/package/@wechatbot/pi-agent), [SDK npm package](https://www.npmjs.com/package/@wechatbot/wechatbot), [latest repository commit](https://github.com/corespeed-io/wechatbot/commit/6914de4e4cae966b1a3f4c6531711c9dffd84fee)).

Two current caveats are source-verified: the Pi package still peers/imports `@mariozechner/pi-coding-agent`, and an open issue requests migration to `@earendil-works/pi-coding-agent`; another open issue reports that closely spaced incoming messages can call Pi while it is already processing because the bridge lacks an inbound queue ([manifest](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/package.json), [compatibility issue #102](https://github.com/corespeed-io/wechatbot/issues/102), [concurrency issue #81](https://github.com/corespeed-io/wechatbot/issues/81)). **Inference:** for current Pi, this is the best feature base but should be forked or patched to the current package namespace and given the queueing behavior used by `pi-wechat` before relying on it unattended.

## 4. General reusable libraries and non-Pi integrations

### Recommended generic SDK: `@wechatbot/wechatbot`

The CoreSpeed repository explicitly describes itself as a WeChat iLink Bot SDK for any agent, inspired by Tencent’s `openclaw-weixin`, and publishes Node.js, Python, Go, and Rust implementations ([English README](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/README.EN.MD), [architecture comparison](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/docs/architecture.md)). The Node package exposes a stable high-level `WeChatBot` API, typed events, middleware, media, file/memory/custom storage, and error types; it has zero runtime dependencies and requires Node 22+ ([public exports](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/src/index.ts), [package manifest](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/package.json)). Its protocol document covers QR status variants, bearer headers, long polling, context tokens, start/stop notification, media upload/download, and the required AES formats ([protocol reference](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/docs/protocol.md)).

The whole repository carries an MIT license, and the latest checked Node package is 2.2.0; repository work continued through 2026-07-02, although several July/August issues and pull requests remained open at the research date ([license](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/LICENSE), [npm package](https://www.npmjs.com/package/@wechatbot/wechatbot), [open issues/PRs](https://github.com/corespeed-io/wechatbot/issues)).

### Closest “adapt OpenClaw to any Agent” library: `weixin-agent-sdk`

`wong2/weixin-agent-sdk` says it is non-official, was modified from `@tencent-weixin/openclaw-weixin`, and connects any backend through `Agent.chat({ conversationId, text, media })`; it also ships `weixin-acp` for ACP-compatible agents such as Claude Code and Codex ([README](https://github.com/wong2/weixin-agent-sdk)). The npm package `weixin-agent-sdk` is MIT, Node 22+, version 0.5.0 from 2026-04-19, and the repository’s latest checked commit is 2026-05-03 ([npm package](https://www.npmjs.com/package/weixin-agent-sdk), [latest commit](https://github.com/wong2/weixin-agent-sdk/commit/c05f68422ce7e6521239e72fa793be9d98ed342b), [license](https://github.com/wong2/weixin-agent-sdk/blob/main/LICENSE)).

The repository’s MIT file permits reuse, but its README also says “仅供学习交流使用” (“for learning and communication only”) ([license](https://github.com/wong2/weixin-agent-sdk/blob/main/LICENSE), [README notice](https://github.com/wong2/weixin-agent-sdk)). **Inference:** the MIT grant and README notice send different commercial-use signals; obtain maintainer/legal clarification before a commercial deployment rather than assuming the README sentence overrides or does not override the license.

### Other reusable/reference implementations

`@pinixai/weixin-bot` supplies a compact Node/Python `login -> onMessage -> reply -> run` API and MIT metadata, but its repository had no commits after 2026-03-22 and the npm package remained 1.2.0 from that date ([repository](https://github.com/epiral/weixin-bot), [npm package](https://www.npmjs.com/package/@pinixai/weixin-bot)). Application-local implementations also demonstrate portability: HKUDS Nanobot states that its Python runtime is aligned with `@tencent-weixin/openclaw-weixin` 2.4.6, while LobeHub, FastGPT, Cherry Studio, DeepChat, and others implement the distinctive `getupdates` protocol in their own channel adapters ([Nanobot source](https://github.com/HKUDS/nanobot/blob/8e77f3f8a44f49cc82119130e6a20cae18c747c3/nanobot/channels/weixin/runtime.py), [LobeHub adapter](https://github.com/lobehub/lobehub/blob/8abf30d72cb18f842806e5d7ff58263182c9a235/packages/chat-adapter-wechat/src/api.ts), [FastGPT client](https://github.com/labring/FastGPT/blob/b9678160078279ea2d462c823eab8c5398b6ca8c/packages/service/support/outLink/wechat/ilinkClient.ts), [Cherry Studio protocol](https://github.com/CherryHQ/cherry-studio/blob/7bb65e75d91fc9ae97e24f4e4c099205dc1c676b/src/main/ai/channels/adapters/wechat/WeChatProtocol.ts)).

## 5. Concrete integration options

### For Pi

1. **Lowest effort, text only:** install and evaluate `pi-wechat`; it is already in Pi’s package directory and queues messages, but it shares one session across users, substitutes placeholders for media, and is lightly maintained ([Pi package page](https://pi.dev/packages/pi-wechat?page=42), [README limitations](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/README.md)).
2. **Best feature base:** fork `@wechatbot/pi-agent`, change its Pi peer/type import to `@earendil-works/pi-coding-agent`, add serialized `streamingBehavior`/queue handling, and add an explicit sender allowlist before `pi.sendUserMessage()` ([extension source](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/src/index.ts), [compatibility issue](https://github.com/corespeed-io/wechatbot/issues/102), [concurrency issue](https://github.com/corespeed-io/wechatbot/issues/81)).
3. **Cleanest owned implementation:** write a small Pi extension over `@wechatbot/wechatbot`: QR command -> `bot.login()`, background `bot.start()`, sender authorization -> queued `pi.sendUserMessage()`, and `agent_end` -> `bot.reply()`. The reusable SDK already owns auth, polling, persistence, context tokens, typing, media, and retries ([SDK exports](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/src/index.ts), [existing Pi bridge](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/src/index.ts)).
4. **Sidecar rather than port:** retain OpenClaw and its Tencent plugin when OpenClaw’s pairing, per-account routing, and channel lifecycle are desired; connect the application/agent behind OpenClaw rather than extracting the transport ([OpenClaw access-control and lifecycle docs](https://docs.openclaw.ai/channels/wechat)). This preserves the supported plugin boundary but keeps OpenClaw as a runtime dependency.

### For any application

- **Node.js:** `@wechatbot/wechatbot` is the most reusable high-level API and has no runtime dependencies; use one isolated bot/storage instance per account and only one active poller per account, as its multi-account guidance specifies ([Node manifest](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/package.json), [multi-account guidance](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/README.EN.MD)).
- **Agent abstraction/ACP:** `weixin-agent-sdk` is closest to a ready-made “arbitrary agent” bridge; implement `Agent.chat`, or use its ACP subprocess adapter ([README/API](https://github.com/wong2/weixin-agent-sdk)).
- **Python/Go/Rust:** use CoreSpeed’s language implementation or treat its protocol document plus Tencent’s types as the interoperability contract ([architecture/language packages](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/docs/architecture.md), [Tencent types](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/api/types.ts)).
- **Direct fork/extraction:** legally possible under Tencent’s MIT code license, but technically higher-maintenance than using a dedicated SDK because the official modules assume OpenClaw configuration, logging, hooks, pairing, and runtime dispatch ([license](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/LICENSE), [OpenClaw imports in channel](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/channel.ts), [OpenClaw imports in processing](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/messaging/process-message.ts)).

## 6. Literal personal-account proxy plugin: separability and risk

The community `@canghe/openclaw-wechat` client is architecturally simple: `ProxyClient` sends an API key and account id to configurable proxy endpoints for status, iPad/Mac QR login, sending, contacts, and webhook registration; `callback-server.ts` receives pushed messages; OpenClaw-specific `bot.ts` performs routing and response dispatch ([proxy client](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/src/proxy-client.ts), [callback server](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/src/callback-server.ts), [OpenClaw bridge](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/src/bot.ts)). **Inference:** an arbitrary app could reuse `ProxyClient` and `callback-server` while replacing `bot.ts`, but it would still depend on the undocumented/private proxy and purchased API key; therefore this is a client extraction, not a reusable open WeChat library.

Security is materially weaker in the checked source: the callback listener binds `0.0.0.0`, accepts JSON at `/webhook/wechat`, and does not authenticate or verify a signature; the `apiKey` option is passed into `startCallbackServer` but never used ([callback server source](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/src/callback-server.ts)). The sample proxy URL is plain HTTP and the client does not enforce HTTPS while sending `X-API-Key`, so a deployment must enforce TLS outside the library ([README configuration](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/README.md), [request code](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/src/proxy-client.ts)). **Inference:** because the proxy performs login, receives messages, and sends as the account, its operator is a high-trust third party with effective control over that automation path.

Maintenance/reproducibility is also poor: the public source has four commits ending 2026-02-13 and its checked-in manifest says 0.1.0, while npm reports 0.1.13 published 2026-02-23 with no corresponding public tags/releases; the manifest’s repository URL also points to a different owner (`woniu/openclaw-wechat`) ([latest source commit](https://github.com/freestylefly/openclaw-wechat/commit/b8e3b4c25d57ec620066cae21517b9befc0e1483), [source manifest](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/package.json), [npm package](https://www.npmjs.com/package/@canghe/openclaw-wechat)). The manifest declares MIT, but the repository contains no standalone LICENSE file in the checked tree ([manifest](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/package.json), [repository tree](https://github.com/freestylefly/openclaw-wechat/tree/b8e3b4c25d57ec620066cae21517b9befc0e1483)).

### Verified restrictions

- Tencent’s channel is a separate bot conversation, not authority to send as the scanning personal account to that account’s friends; it advertises direct chats, not groups ([maintainer response](https://github.com/Tencent/openclaw-weixin/issues/52#issuecomment-4407647606), [capabilities](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/channel.ts)).
- Multiple bot accounts can be registered, but each account/conversation requires correct isolation and context-token handling ([Tencent README](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md), [context-token protocol](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/docs/protocol.md)).
- The official plugin and the checked general Node SDKs require Node 22+ ([Tencent manifest](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/package.json), [CoreSpeed manifest](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/package.json), [`weixin-agent-sdk` npm](https://www.npmjs.com/package/weixin-agent-sdk)).
- A reply requires an inbound `context_token`; proactive delivery therefore depends on having a valid remembered conversation context ([Tencent protocol](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md), [CoreSpeed protocol](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/docs/protocol.md)).

### Security and ToS assessment

**Verified security facts:** OpenClaw applies its normal sender pairing/allowlist model to this channel, but the two Pi bridge implementations inject received messages directly into Pi and do not implement OpenClaw pairing ([OpenClaw access control](https://docs.openclaw.ai/channels/wechat), [`pi-wechat` injection](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/index.ts), [`@wechatbot/pi-agent` injection](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/src/index.ts)). Pi’s own package directory warns that third-party Pi packages can execute code and influence agent behavior ([Pi package security note](https://pi.dev/packages/pi-wechat?page=42)).

**Inference:** an unapproved WeChat sender can become a remote prompt source for a tool-capable Pi session unless the bridge adds a sender allowlist/pairing gate, a dedicated least-privilege Pi session, and queue/session isolation. This risk follows directly from the bridges’ unguarded `pi.sendUserMessage()` paths and their documented shared-session behavior ([`pi-wechat` source](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/index.ts), [`pi-wechat` limitations](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/README.md), [`@wechatbot/pi-agent` source](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/src/index.ts)).

Bot bearer tokens and context state are stored as plaintext JSON with restrictive file permissions (`0600`, directories `0700` where implemented), so host compromise or careless backup/logging still exposes live credentials even though local file permissions reduce cross-user access ([Tencent account storage](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/src/auth/accounts.ts), [CoreSpeed file storage](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/src/storage/file.ts), [`pi-wechat` storage](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/auth.ts)).

The Tencent repository’s MIT license grants rights in the software, not an explicit license to Tencent’s hosted iLink service ([MIT license](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/LICENSE)). The official source nevertheless documents a custom `bot_agent` identifier for non-default app names and publishes the backend protocol, which is evidence that multiple upstream applications are technically anticipated, but it does not by itself state the service eligibility or commercial-use rules for arbitrary clients ([custom BotAgent and protocol](https://github.com/Tencent/openclaw-weixin/blob/cef0bfc390393f716903e16d50408118047f87e0/README.md)).

**Unverified ToS point:** I did not locate a Tencent-hosted public copy of any ClawBot-specific service terms during this run. Tencent’s general WeChat software agreement is public, but it does not substitute for a ClawBot-specific eligibility determination ([general WeChat agreement](https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=default&head=true)). **Inference:** direct iLink use through a Tencent-maintained bot protocol is lower account-ban risk than desktop injection or third-party personal-account proxying, but production/commercial use outside OpenClaw should be confirmed with Tencent and tested under the terms shown during QR authorization rather than inferred from the MIT code license.

## Recommendation

For this Pi repository, the most practical path is to **build on `@wechatbot/wechatbot`, using `@wechatbot/pi-agent` only as reference code**, then add the current `@earendil-works/pi-coding-agent` types, sender allowlisting/pairing, serialized inbound work, per-sender or dedicated-session isolation, secret redaction, and explicit shutdown/re-login handling ([SDK](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/nodejs/src/index.ts), [reference extension](https://github.com/corespeed-io/wechatbot/blob/6914de4e4cae966b1a3f4c6531711c9dffd84fee/pi-agent/src/index.ts), [known Pi compatibility issue](https://github.com/corespeed-io/wechatbot/issues/102), [known queue issue](https://github.com/corespeed-io/wechatbot/issues/81)). Use `pi-wechat` only when text-only, single-session behavior is acceptable; use an OpenClaw sidecar when OpenClaw’s existing pairing/routing is more valuable than removing the host dependency ([`pi-wechat` limitations](https://github.com/yangyang0507/pi-wechat/blob/8f351ce82ac6a15c09581e6f9c8c7678e44f055f/README.md), [OpenClaw lifecycle/access control](https://docs.openclaw.ai/channels/wechat)).

Do **not** base a new integration on the community personal-account proxy unless that exact capability—acting through a personal account rather than a ClawBot—is mandatory and the proxy operator, account-policy position, webhook authentication, TLS, source/package mismatch, and commercial terms are independently resolved ([proxy README](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/README.md), [unauthenticated callback](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/src/callback-server.ts), [source manifest](https://github.com/freestylefly/openclaw-wechat/blob/b8e3b4c25d57ec620066cae21517b9befc0e1483/package.json), [npm package](https://www.npmjs.com/package/@canghe/openclaw-wechat)).
